# Правило: git

- **Никогда** не делай force push без явной просьбы пользователя.
- **Никогда** не делай `git commit --amend` для уже отправленных коммитов. Вместо этого — новый коммит.
- **Никогда** не пропускай pre-commit хуки (`--no-verify`) без просьбы.
- Не делай `git reset --hard` или `git checkout --` без подтверждения — это разрушительно.
- Один логический change = один commit. Не смешивай рефакторинг с фичей.
- Сообщение коммита объясняет **зачем**, не **что** (код покажет что).
- При неудаче pre-commit хука: исправь проблему, re-stage, сделай **новый** коммит (не amend).

## Worktree placement

- Git worktree создавай **в `<repo>/.worktrees/<branch-name>/`**, не в глобальной директории.
- Папку `.worktrees/` всегда добавляй в `.gitignore` репо (один раз) — иначе git попытается включить её в индекс.
- Если в репо уже есть конвенция — следуй ей, не создавай параллельную.
- Глобальный путь использовать **нельзя** (нарушает локальность репо, осложняет cleanup).
- При cleanup'е merged-веток: `git worktree remove <path>` + `git branch -d <branch>`.
