4 уровня AI-Native разработки

Level 1: Вайб-кодинг

Спросил ChatGPT → вставил код → надеешься что работает

Level 2: Контекст и правила

AGENTS.md, CLAUDE.md, rules/ — AI помнит проект между сессиями

Level 3: Верифицированная разработка

Мульти-агентный code review, security audit, confidence filtering

Level 4: Автономные агенты

Агенты запускают агентов, DAG-оркестрация, авто-восстановление

Level 2: Контекст

Проблема: AI забывает всё между сессиями


Каждая новая сессия — как новый сотрудник на работе.

Без онбординга он будет делать по-своему.


AGENTS.md — онбординг-документ для AI-агентов.

Один файл в корне проекта = постоянная память.

Level 3: Верификация

«Доверяй, но проверяй» — для AI-кода


AI написал код. Кто его ревьюит?


Раньше: другой человек (медленно, дорого)

Сейчас: другой AI-агент (мгновенно, параллельно)

Ключ: мульти-агентная архитектура

Архитектура review-плагина

PHASE 1: REVIEW
TeamCreate → 5 Sonnet-агентов параллельно:
code-reviewer · bug-hunter · security-scanner · error-auditor · architecture-reviewer
PHASE 2: SCORING
Haiku-скореры перепроверяют каждую находку → confidence 0-100
Фильтр: только ≥ 80 попадают в отчёт
PHASE 3: FIX → TEST → RE-REVIEW
Автофикс → сборка → тесты → повторный review (до 3 итераций)

Принципы AI-Native Engineering


📄 Контекст — это код. AGENTS.md коммитится в git, ревьюится в PR.

🔍 AI проверяет AI. Один агент пишет, другие ревьюят.

📊 Confidence > opinion. Числовая оценка вместо субъективного мнения.

🔄 Fix loop. Review → Fix → Test → Re-Review — до чистоты.

🏗️ Инфраструктура масштабируется. Правила один раз, применяются в каждой сессии.

Итого


1. Контекст — AGENTS.md в каждый проект

2. Правила — rules/ коммитятся, не объясняются устно

3. Верификация — мульти-агентный review перед каждым PR

4. Измеримость — confidence scoring, не «мне кажется»


AI не заменяет инженера. AI меняет что значит быть инженером.
